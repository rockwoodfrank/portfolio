Originally developed to remove third-party dependencies, my codebase
constantly collects live data from CCTV cameras located across the district.
This data is parsed and stored in a MongoDB database, which can then be accessed
through a React dashboard to display time series graphs of vehicle traffic based on
movement and object type, live maps of the locations and the detected objects in real time,
and heatmaps of the locations based on traffic flow. The system was capable of collecting
data from two cameras at the same intersection, and combining their data to get a complete
record of traffic behavior. This technology is being implemented across the district,
with the intention to use this data to make safer intersections for all.

## Problem Statement
Many solutions exist on the market for gathering traffic usage information that integrate
computer vision to determine object type and obtain more accurate movement patterns.
The issue with many of these solutions, however, is that the data collected is stored
on vendor servers, and requires a monthly fee for access to the data, usually per location.

Two main issues arise with these solutions. First, the data access fee is a recurring
expense which grows larger for each site set up. Second, storing the data on a vendor
server about traffic patterns of public roads raises ethical concerns. As long as the
data is being exported externally, there is no guarantee that all data will remain
uncompromised.

My goal with this project was to:
1. Determine if it was possible to access the stream from the camera, and
2. Design a system to collect, parse, and display that data.
